# Cooperators MBT harness

Replays two Apalache witness batteries through ModelMirrors and MirrorRust:

- **protocol**: 34 traces of [`../MBCooperators.tla`](../MBCooperators.tla)
  against in-process `DaemonState` (no sockets).
- **writers**: five traces of [`../MBWriters.tla`](../MBWriters.tla) against
  real daemon subprocesses sharing or separating bus roots (requires UDS).

Each step's observed state must match the trace; divergences produce field-level
diffs. The writer suite observes real process and filesystem state. The protocol
suite retains the reconstructed-log limitation described below.

The new [failure/recovery contract](faults/README.md) adds nineteen TLC-generated
ITF scenarios covering the reviewed hardening defects and per-launch identity.
Its model matrix has 48 checks, plus 40 fixed-input checks that verify the
traces distinguish all 21 faulty policies. A standalone prototype driver requires real
fault/barrier capabilities, authoritative observations, and an actual-receipt
ledger; it never sends expected observations to an adapter. That Python/NDJSON
prototype is not generated by the model-interface compiler. Integration should
extend the reviewed compiler contracts, regenerate/check Rust bindings, and
implement the added generated trait methods and real fault hooks. The existing
`--suite all` below continues to mean the two
implemented suites, protocol and writers; it does not include the new gate.

## Generated adapter (model-interface compiler)

The Mirrors model-interface compiler (`mirrorrust-v2`) generates the port
traits, typed inputs/observations, codecs, dispatch bindings, semantic digests,
and coverage plumbing. `CoopSut` and `WriterSut` provide the handwritten Rust
implementations of those generated traits. The pipeline:

```bash
GEN=/home/nzsn/Repos/Mirrors/.lake/build/bin/model_interface_gen
# 1. draft contract from spec + trace evidence (evidence states must not
#    contain constant fields; strip Agents/Keys/MaxAttempts/Q/D first;
#    corpus must be content-unique, <= 32 members)
$GEN scaffold --replace --spec ../MBCooperators.tla --param-var parameters \
    --proposal Cooperators.mirror-interface.json --evidence T1 --evidence T2 ...
# 2. review: trim each action's inputs to actual usage (done, committed)
# 3. resolve to the reviewed lock
$GEN resolve --spec ../MBCooperators.tla --contract Cooperators.mirror-interface.json \
    --evidence <one trace> --param-var parameters --lock Cooperators.mirror-interface.lock.json
# 4. generate the typed adapter (port trait, codecs, digest, coverage)
$GEN generate --lock Cooperators.mirror-interface.lock.json --target mirrorrust-v2 --out generated
# 5. verify the whole chain
$GEN check --spec ../MBCooperators.tla --contract Cooperators.mirror-interface.json \
    --evidence <one trace> --param-var parameters \
    --lock Cooperators.mirror-interface.lock.json --target mirrorrust-v2 --out generated
#    → "model-interface check clean"
```

`src/main.rs` implements the generated `MBCooperatorsPort` trait against the
daemon; the generated `MBCooperatorsBinding` does wire dispatch, typed input
decoding, observation encoding, lifecycle (init-gating/poisoning), and per-action
coverage. Unexpected protocol daemon rejections surface as immediate replay failures
(`adapter_failure`), not later state mismatches.

**Limit:** the negotiated client path (`run_client_with_traces_negotiated`,
which would also verify the semantic digest server-side) requires
`mirrors.model-interface-negotiation/v1`, unsupported by ModelMirrors 0.1.1.0.
Replay therefore uses the plain trace path; the digest binding is verified
locally by `model_interface_gen check` instead.

## Prerequisites

- `apalache-mc` on `PATH` (used directly for trace generation — see below).
- `MIRROR_BIN` pointing at a built ModelMirrors executable (used as the replay
  server over stdio; no sockets needed).
- Offline cargo: `cargo build --offline --locked` (the lockfile pins only
  registry crates already extracted on this machine).

## Run

```bash
cd spec/mbt
MIRROR_BIN=/path/to/ModelMirrors cargo run --offline --locked   # generate + replay
MIRROR_BIN=... cargo run --offline --locked -- --skip-gen       # replay committed traces only
MIRROR_BIN=... cargo run --offline --locked -- --skip-gen --suite writers
MIRROR_BIN=... cargo run --offline --locked -- --skip-gen --suite protocol
```

A trace mismatch produces a nonzero exit status. Committed protocol traces
live in `traces/`; writer traces live in `writers/traces/`.
The default suite is `all`. Missing `MIRROR_BIN`, missing required writer
traces, startup/tool errors, and unavailable sockets also fail the run; writer
coverage is never silently skipped. Use `--suite protocol` explicitly in a
socket-denying sandbox when only that suite is intended.

## Multiple-writer suite

`src/writers.rs` implements the generated `MBWritersPort`. Its internal
`--writer-child` subprocess calls the production `server::run_with_options`
with HTTP disabled. Children share a prepared registry and inbox on the same
root, or receive independent roots. Socket paths are passed per child through
`COOP_SOCKET`; parent environment variables are not changed.

| Trace | Required behavior |
|---|---|
| `NoCompeteW1` | With w1 serving r1, w2 using a different socket must be refused. |
| `NoCompeteW2` | The reverse startup order must also refuse the second writer. |
| `NoIndependentRoots` | Two roots, each using its own `run/daemon.sock`, both serve messages. |
| `NoHandoff` | Kill/wait the first writer, start its successor, and preserve message/sequence continuity. |
| `NoRejectedRecovery` | A same-socket competing start must reject without repairing or appending to the active owner's torn-tail log. |

`Start` in the model is an **attempt**, including observable rejection. It is
enabled while another writer owns the root, so the replay actually exercises
the rejection boundary. This differs from the old model's action-disabling
representation of rejected operations.

Writer observations are independent of predicted model state:

- `writers`: children that remain alive and responded with their own PID.
  Checking PID avoids accepting the first daemon's response as readiness of a
  second daemon on a shared socket.
- `rejected`: child exit status classified from the daemon's actual startup
  error (`AddrInUse`, `AlreadyExists`, or `WouldBlock`). Other startup errors,
  including socket denial, fail the adapter.
- `records`, `seqs`, `valid`, `torn`: read-only inbox bytes, message tags,
  actual sequence numbers, verified hash links, and the injected incomplete
  suffix. Observation never opens `LogFile`, which could repair the evidence.
- `rejectedReadOnly`: byte-for-byte comparison of durable regular files before
  and after a rejected startup, excluding the `run/` socket directory.

The torn-tail action is a controlled fixture injection into a temporary root,
not evidence of a naturally occurring storage failure. Starts are ordered
deterministically while process lifetimes overlap; simultaneous startup races,
symlink aliases, and crash/power-loss atomicity are outside this battery.
All children are killed and waited on when each trace finishes. Failed trace
roots and child stderr logs are retained under `/tmp/coop-writers-mbt-*` and
their paths appear in the failure report; passing fixtures are removed.

```sh
# From spec/mbt: generate the five bounded witnesses (length <= 6).
python3 generate_writers.py

# From spec: resolve, generate, then check the reviewed companion contract.
GEN=/home/nzsn/Repos/Mirrors/.lake/build/bin/model_interface_gen
$GEN resolve --spec MBWriters.tla \
  --contract mbt/writers/CooperatorsWriters.mirror-interface.json \

  --lock mbt/writers/CooperatorsWriters.mirror-interface.lock.json

  --target mirrorrust-v2 --out mbt/writers/generated
```

As with protocol replay, this suite uses the plain ModelMirrors trace path;
server-side semantic-digest negotiation remains unavailable. The local compiler
check binds source, reviewed contract, evidence, lock, and generated adapter.

**The updated MBT gate is red on the current broker:** 39 traces, three failed.
The 34 protocol traces and the independent-root/handoff writer controls pass.
Both different-socket contenders are accepted, violating exclusive ownership.
The same-socket contender rejects only after truncating the injected suffix and
appending a recovery record, violating rejected-startup non-mutation.

Validation used the unchanged core source in an isolated Cargo build with the
unused HTTP module stubbed, because the offline cache lacks pinned
`hyper 1.11.1`. These writer runs exercised real UDS sockets and subprocesses
with the production startup/recovery path and HTTP disabled. They do not
qualify the full pinned binary or its HTTP transport. Generated-interface
`check` passes, all five writer actions are covered by corpus preflight, and
Apalache reports no violation of `RootWriterExclusive` through length six.
Production code has not been changed to make this gate green.

## Trace battery

Eight witness invariants in `MBCooperators.tla`: `TraceComplete` (12 distinct
full-length behaviors via `--view=View` dedup) plus action-forcing witnesses
`NoAck`, `NoCrash`, `NoRelease`, `NoExpire`, `NoComplete`, `NoFail`, `NoDead`
(2 each; the length-bounded base battery never contains ack/crash/release
steps because they do not grow the log). Current battery: 34 traces covering
send/ack/claim/expire/complete/fail/release/publish/update/crash.

## Protocol oracle boundary (read before trusting)

- Replay checks that the sampled model-enabled actions succeed on the daemon,
  observes ack cursors, and compares a reconstructed abstract log. It does not
  independently establish all durable effects or complete enabled-action
  equivalence. Rejection paths (VERSION_CONFLICT, CONFLICT_CLAIMED, LEASE_LOST)
  are *not* probed by traces. TLC on `../Cooperators.tla` checks the corresponding
  abstract safety constraints; implementation rejection behavior still needs
  Rust tests.
- The adapter reconstructs the abstract `log` from successful daemon effects
  (call order == effect order, single-writer daemon), and reads ack cursors
  back authoritatively via `wait_message` (so `crash` reset is really
  observed). Lease `fence` values are abstract log positions; concrete fences
  (per-resource seqs) are exercised functionally, not compared numerically.
- Constant vars (`Agents`, `Keys`, `MaxAttempts`, `Q`, `D`) are not part of
  the compared state.

The adapter retains its shadow `log` across daemon restart; it does not rebuild
that observation by reading the recovered durable logs. A successful call with
incorrect persistence can therefore escape detection unless a later action
exposes the divergence. The hardening obligations in
[`../CooperatorsHardening.tla`](../CooperatorsHardening.tla) require additional
failure injection and authoritative implementation observations before they
can be claimed as MBT-covered. Root ownership and rejected-startup mutation now
have the separate real-process writer coverage above; the other hardening
scenarios still require additional adapters and traces.

`faults/traces/` now supplies those failure-focused scenarios and the associated
observation/injection contract. The implementation port and fault seams remain
missing, so this is test preparation rather than new implementation coverage.

## Findings and limits recorded during bring-up

- **Dead-letter semantics caught by MBT:** the first battery failed 3 traces
  on the sequence claim→expire→claim→fail→**claim**. The implementation
  increments its attempt counter *at claim time* and dead-letters on the
  `MaxAttempts`-th failed delivery; the MBT spec modeled death one terminal
  later. Spec fixed (`Dead == AttemptsQ >= MaxAttempts`), consistent with the
  TLC-verified spec.
- **ModelMirrors gen protocol inlines all traces in one response line**, which
  overflows MirrorRust's 64 KiB protocol-line cap beyond ~3 Cooperators-sized
  traces. Generation therefore runs `apalache-mc` directly (exit 12 = witness
  found); ModelMirrors is used only for replay, whose messages are small.
- Deterministic expiry uses the daemon's `#[doc(hidden)]`
  `debug_force_expire_queue/doc` hooks — the exact sweeper event path with an
  infinite clock. Never used in production paths.
