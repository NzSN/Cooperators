The adapter ports are already generated

You are correct. The model-interface compiler generates the existing Rust port traits and adapter bindings. The handwritten work is the concrete Rust implementation of those traits, including calls into Cooperators and any real fault-injection hooks.

A generated trait declares which operations an implementation must provide. It does not infer how to make a specific filesystem sync fail after bytes were written. That behavior belongs in a real Rust hook invoked by the trait implementation.

What the earlier explanation got wrong

I described the missing fault support as though it required building the adapter interface from scratch. That blurred two layers: the compiler-generated port/binding and the handwritten SUT implementation behind it.

I also introduced replay_faults.py and a separate cooperators.fault-port/v1 NDJSON contract. That is a standalone prototype outside the existing generated-adapter pipeline. It should not have been presented as the required architecture for adding fault coverage.

The corrected integration direction is to extend the reviewed model-interface contracts, regenerate/check the compiler-owned bindings, and implement the additional trait methods and real Rust fault hooks. The separate custom transport does not need to become another maintained adapter architecture.

The failure model, nineteen traces, observation rules, and trace-discrimination checks remain useful preparation. They do not establish compiler integration or implementation correctness. No checked-in compiler-generated binding or concrete Rust SUT implementation for the new MBFaults scenarios exists yet.

What remains for the new fault scenarios

  1. Extend the model-interface description. Add the fault actions, required inputs, explicit operation results, and authoritative observations to a reviewed compiler contract. Verify compiler acceptance of the profile-specific observation shapes.
  2. Regenerate the interface. Use the existing scaffold/review → resolve/lock → generate → check workflow. The compiler owns generated Rust files; they should not be edited manually.
  3. Implement the added generated trait methods. Invoke the real Rust I/O, clock, process, and recovery seams. Capture actual responses, returned receipts, cursors, records, and identities.
  4. Wire those generated bindings into the existing MirrorRust/ModelMirrors harness. Expose modeled rejections and injected I/O-error outcomes as observations. Unexpected adapter failures remain binding errors.
  5. Fix the owning production code. The root lock, uncertain-writer recovery, expiry cursor, dead-letter reconciliation, publication retry, status scan, rotation, and fresh-launch provisioning changes still belong in Cooperators itself.

For example, adding a modeled sync-failure action can produce a new typed port method and a result observation. Its Rust implementation must arrange the real sync failure and record the actual error. The storage fix must then quarantine or reconcile the uncertain writer. Regenerating a binding alone changes neither filesystem behavior nor recovery correctness.

The previously recorded 48 model checks, 40 fixed-input checks, and 22 tool tests remain model/prototype evidence. This correction did not run a compiler generation/check or new Rust replay for MBFaults.
