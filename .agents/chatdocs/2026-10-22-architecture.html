Architecture of the Cooperators broker

A description of the system as implemented at commit 3bb638d: one daemon owns durable logs on a single machine, and Codex, Claude, and CLI sessions reach it through a Unix socket, an MCP stdio adapter, or a loopback HTTP endpoint. Normative decisions stay in the numbered design documents; this page describes the current functional architecture and its evidence boundaries.

1. System overview

Cooperators is a localhost inter-agent message broker. A single cooperatorsd process (coop daemon run) owns all durable state for a bus root (default $HOME/.local/share/cooperators) behind an exclusive root-ownership lock. Everything is local: the primary transport is a Unix-domain socket, the optional HTTP MCP endpoint binds to 127.0.0.1:7420, and the trust boundary is filesystem permissions plus bearer tokens. There is no TLS and no at-rest encryption.

A third backend, coop mcp-stdio --embedded, serves a bus root in-process without a daemon. It exists for tests that cannot bind sockets and for single-process debugging; the daemon remains the only writer in normal operation.

2. Process and concurrency model

The daemon is a Tokio multi-threaded process built around Arc<DaemonState> (src/server.rs), which holds configuration, the registry, every subsystem, and the root lease.

3. Storage architecture

All durability is append-only JSONL with a SHA-256 hash chain (src/storage.rs). Records commit in the order append → fsync → ack. Startup replays logs and truncates a torn tail — a crash between append and fsync drops only never-acknowledged records. After an uncertain write or sync failure, the writer is quarantined until reopened and recovered.

<root>/                       # 0700
  run/daemon.sock          # UDS listener, 0600
  registry.json            # agent identities; only SHA-256 token digests, 0600
  agents/<id>/             # inbox.jsonl, dedupe index, cursors
  channels/<name>.jsonl    # replayable (file, seq) cursors
  queues/<name>.jsonl      # enqueue/claim/lease/complete/fail records
  dead/                    # dead-letter streams
  docs/, blobs/sha256/     # versioned documents; bodies >64 KiB spill to blobs
  .segments/<file>/        # sealed rotation segments

Channel, queue, document, and dead-letter streams rotate at DaemonConfig::log_rotation_bytes (default 256 MiB) into .segments/; logical cursor filenames and global sequence numbers stay stable. Inbox and expiry logs are unsegmented.

Documented limit: the hash chain authenticates links, so a modified final record is undetectable until the next append (recorded in src/storage.rs).

5. Arrival pipeline and managed hosts

Arrival notifications (design 0004)

Source events — inbox, queue, and document writes — remain authoritative; there is no completion WAL. The arrivals subsystem scans source logs, matches exact per-agent subscriptions, and materializes a separate durable arrival feed per recipient with its own peek/ACK cursor, so feed consumption and source consumption advance independently. Feed workers are finite and restart-safe: after a crash, projection replays sources and resumes obligations. Feed errors stay visible in ArrivalStatus until a successful retry; no failed or full feed discards its source obligation.

Managed host activation

The host bridge (host/bridge.rs) journals notice receipt before broker ACK, binds one agent identity to one exact provider session (Binding with a generation counter), and coalesces wakes. Adapters (host/adapters.rs) drive managed Codex App Server and Claude duplex sessions. The managed CLI (host_cli.rs) launches new sessions or explicitly resumes existing ones; it never selects a latest conversation or forks a session implicitly.

Codex creation is a separate no-turn bootstrap: initialize, thread/start, then thread/name/set materialize a durable named thread and its exact ID before the managed resume connection opens. No turn/start is needed to create that binding. Claude binds an explicit session UUID through its persistent streaming protocol.

Fail-closed lifecycle

  • Exact binding and generation fencing: adapter calls reject another bus, identity, workspace, session, binding, or generation. A wake is not evidence of observation or resolution by itself.
  • Closed means terminal: the duplex reader fences every frame queued behind a fatal transport/protocol error. Both Codex and Claude pump loops also stop when the process is closed or adapter state is Offline, preventing buffered approvals, echoes, or status changes from reviving the session or producing delayed wake acceptance.
  • Approvals stay explicit: operator requests are retained until answered or withdrawn. Bootstrap rejects an unexpected operator request rather than silently granting it, and provider approval configuration remains per launch.

6. Identity and security boundary

  • The trust boundary is the local machine plus filesystem permissions: UDS 0600, bus root 0700, registry.json 0600. Any local process that can open the socket still needs an agent token; only SHA-256 digests are stored.
  • HTTP is loopback-only by default with bearer auth on every request including initialize; /healthz is the only unauthenticated route. Binding it off-loopback requires adding TLS and an authentication story first.
  • An agent instance is one launched session; identity survives its own reconnects but is never shared across launches. Display names are non-unique labels; routing uses unique IDs (vocabulary: CONTEXT.md).
  • Bus IDs and a registry V2 guard let a preserved pre-upgrade binary refuse an upgraded root before touching guarded files.

7. Verification architecture

Functional correctness evidence is layered. Each layer has a distinct boundary; a passing deterministic suite is not treated as proof of live provider behavior.

  1. TLA+ specifications (spec/) — models of idempotency, claim separation, fence freshness, CAS chains, hardening, and instance identity, checked at finite bounds.
  2. Generated model replay — arrival/bridge reference-model traces and the generated MirrorRust/ModelMirrors protocol, ownership, and fault ports. The retained parent-commit qualification covers all 128 arrival/bridge traces and 63 generated MBT traces.
  3. Fault and crash controls — mbt-injection hooks and actual SIGKILL controls cover group commit, rotation, arrival recovery, and the preserved preupgrade binary’s V2 refusal before guarded-file repair.
  4. Protocol conformance — golden transcripts and schema contracts check UDS/stdio/HTTP parity for the 28-tool broker catalog; host fixtures exercise exact sessions, approvals, lost replies, restart, and buffered-frame closure.
  5. Scoped real-provider acceptance — retained Codex CLI evidence covers managed document wakes, activation nonces, pinned reads, explicit approvals, resolution, and one exact-binding restart. It does not qualify every provider flow.
Evidence at 3bb638d. The current terminal-Offline guard passed all 17 host-adapter tests in both normal and mbt-injection modes. The broader 181-test normal and 230-test injection aggregates, 128 arrival/bridge traces, 63 generated MBT traces, crash controls, and scoped real Codex acceptance are retained evidence for parent commit 1e00af4, not a fresh full qualification of this page’s exact commit.

Socket gates use COOP_REQUIRE_UDS=1 so denied AF_UNIX access fails rather than silently passing. Performance validation is intentionally excluded from this edition; no performance benchmark was run for it.

8. Current limitations and open functional work

Functional acceptance remains scoped. The broker and managed-Codex evidence is substantial, but it is not blanket acceptance of every provider, workflow, or restart ordering. See the current docs/impl/arrivals-20261021/HANDOFF.md and resumed qualification record.
  • Real Claude activation is not qualified. The retained run could not start because the installed Claude Code lacked authentication/provider configuration. Its installed protocol version must be qualified afresh after intentional configuration.
  • Real Codex coverage is bounded. Queue adoption, additional restart orderings, and provider-side lost replies remain outside the passing live document-activation run, although related deterministic tests pass.
  • Modern Claude MCP discovery remains open. Default modern negotiation compatibility is independent of the managed host-path evidence and the earlier legacy workaround.
  • Current-commit evidence is targeted. After the terminal-Offline guard, the 17 normal and 17 injection host-adapter tests were rerun. A new full aggregate, generated-MBT, or live-provider campaign was not run for 3bb638d.
